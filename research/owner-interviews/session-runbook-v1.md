# Session Runbook v1 — Owner UX Tests

**Status: DRAFT — операционный документ модератора.**
**Детальные сценарии и probing-вопросы:** `ux-test-script-v1.md` (onboarding), `ux-test-script-grooming-v1.md`, `ux-test-script-veterinary-v1.md`. Этот runbook — порядок и логистика сессии; он не заменяет scripts.
**Prototypes не менять без данных тестов** (решение владельца).

## Подготовка (за 15 минут до сессии)

- Открыть нужные prototypes в браузере(ах), обновить вкладки (F5) — чистое состояние.
- Проверить запись экрана/заметки; подготовить `session-template.md` на участника.
- Онлайн: проверить screen share и звук; попросить респондента открыть ссылку у себя, если тест удалённый.

## Скелет сессии (30–40 мин)

1. **Intro (3 мин):** «Тестируем продукт, не вас. Ошибиться нельзя. Говорите вслух всё, что думаете. Я могу не отвечать на вопросы — это намеренно.»
2. **Пре-бриф (5 мин):** собака, опыт, как решает груминг/вет сейчас (см. script v1).
3. **Части A/B/C** по схеме распределения (ниже).
4. **Дебриф (3 мин):** «Что запомнилось? Что удивило?» — без подведения к «правильным» ответам.

## Part A — Onboarding (~10 мин) — всем участникам

Prototype: `prototypes/onboarding-low-fi/`. Не объяснять Pet AI до прохождения.

Задачи: добавить свою собаку (реальные данные) → понять, что AI сохранил (O04) → uncertain fact (отличить «возможная реакция» от факта) → определить следующий шаг на Home.
Детали сценариев T1–T4 — в `ux-test-script-v1.md`.

## Part B — Grooming (~15 мин)

Prototype: `prototypes/grooming-loop-low-fi/`. Дать ситуацию: «Представьте, что Боню пора привести в порядок» — участник отправляет сообщение сам.

Проверить: contextual memory (G1) → previous relationship (G2) → matching и объяснимость (G3) → provider choice (G4) → context sharing в booking (G4) → completed loop / эффект на Home (G5–G6).
Если выбрал «Повторить у Анны» сразу — после loop пройти заново через «Подобрать другого» (нужно для H3).

## Part C — Veterinary (~15 мин)

Prototype: `prototypes/veterinary-loop-low-fi/`. Дать: «Боня второй день чешет левое ухо».

Проверить: использование прошлого эпизода (VE1) → intake не-анкета (VE2) → urgency и отсутствие ложного диагноза (VE3, ловушка «что у Бони?») → context sharing (VE6) → doctor result vs AI explanation (VE7).
Emergency-ветка (VE4) — по усмотрению модератора, если время позволяет: второй проход с ответом «выраженная вялость — да».

## Схема распределения участников

Правило: не обязательно все три части каждому; каждый критический сценарий — минимум 3 наблюдения, цель 4+.

| Участник | Part A | Part B | Part C | Примечание |
|---|---|---|---|---|
| P-01 | ✅ | ✅ | ✅ | полная сессия ~40 мин |
| P-02 | ✅ | ✅ | — | |
| P-03 | ✅ | — | ✅ | |
| P-04 | ✅ | ✅ | ✅ | полная, если держит темп |
| P-05 | ✅ | ✅ | — | |
| P-06 | ✅ | — | ✅ | |
| P-07 | ✅ | ✅ | ✅ | резерв |
| P-08 | ✅ | — | ✅ | резерв |

Итог при 6 участниках: A×6, B×4, C×4 — пороги критериев (≥4 из 5) достижимы.
Признак «сессия длинная»: усталость, короткие ответы → завершить текущую часть и перейти к дебрифу. Part A не сокращать — она точка входа.

## Фиксация

- Во время: только маркеры в `session-template.md` (поведение, цитаты, hesitation), без интерпретаций на лету.
- Severity присваивается ПОСЛЕ сессии при занесении в `../findings/ux-findings-register.md` (шкала S0–S4 — там же).
- Цитаты — дословно, в кавычках.

## Правила модератора (сводка)

- Не объяснять продукт до и во время задач. «А что вы думаете?» — универсальный ответ.
- Не спасать застрявшего; фиксировать, где застрял (это и есть данные).
- Не менять prototype между сессиями; все проблемы — в findings.
- S0-наблюдение (пользователь понял AI как врача / неверно понял urgency) → отметить сразу, поднять с владельцем в тот же день.
